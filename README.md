# CNN-data-collection-bot

Бот на Node.js (mineflayer). Заходит на ваниль-сервер, переходит в spectator, следит за игроком через `/spectate` и пишет блоки вокруг себя в куб `size × size × size`. Для каждого игрока отдельный файл. Сжатие gzip идёт в отдельном потоке (`worker_threads`).

## Установка и запуск

```bash
npm i mineflayer vec3 prismarine-block
node recorder.js
```

1. Бот заходит на сервер (настройки в `CFG` в начале файла).
2. Выдай ему op: `/op Recorder`.
3. Он сам делает `/gamemode spectator` и `/spectate <ник>`.

## Команды в терминале

| Команда | Что делает |
|---|---|
| `<ник>` | переключиться на игрока (текущая запись закрывается, начинается новая) |
| `list` | кто онлайн |
| `auto` | снова брать первого попавшегося |
| `quit` | корректно закрыть файлы и выйти |

Если ник не указан, бот берёт первого игрока из списка. Когда текущий игрок выходит, запись закрывается и бот переключается на следующего, для него создаётся новый файл.

## Настройки (`CFG`)

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `size` | 48 | сторона куба (±size/2 вокруг бота) |
| `everyTicks` | 20 | снимок раз в N тиков (20 = 1 раз в секунду) |
| `gzipLevel` | 3 | 1 быстрее, 9 меньше файл |
| `outDir` | `data` | папка для записей |

## Выходные файлы

На каждую запись пара файлов:

- `ник_время.bin.gz` — кадры (после распаковки идут подряд)
- `ник_время.json` — метаданные и палитра

Кадр после распаковки:

| Поле | Тип | Размер |
|---|---|---|
| номер кадра | uint32 LE | 4 Б |
| x0, y0, z0 (угол куба) | int32 LE ×3 | 12 Б |
| блоки | uint16 LE × size³ | size³ × 2 Б |

Индекс блока: `(dy*size + dz)*size + dx`. Значение — `stateId` блока (учитывает состояние: ориентацию, уровень воды и т.д.). `0` — воздух, `65535` — чанк не загружен.

`.json` содержит палитру `stateId → { name, props }` только для встреченных блоков, размер куба и число кадров.

В данные не пишутся: позиция и взгляд игрока, сущности, содержимое контейнеров, освещение, биомы.

## Чтение в Python

```python
import gzip, json
import numpy as np

meta = json.load(open("Steve_....json"))
S = meta["size"]
fb = 16 + S**3 * 2
raw = gzip.open("Steve_....bin.gz", "rb").read()
n = len(raw) // fb

frames = np.empty((n, S, S, S), np.uint16)   # [кадр][y][z][x]
origins = np.empty((n, 3), np.int32)
for i in range(n):
    o = i * fb
    origins[i] = np.frombuffer(raw[o+4:o+16], np.int32)
    frames[i] = np.frombuffer(raw[o+16:o+fb], np.uint16).reshape(S, S, S)
```

## Теоретическое потребление

Размер кадра без сжатия: `16 + size³ × 2` байт.

| size | Блоков в кадре | Размер кадра | 1 кадр/с, час | 1 кадр/с, сутки | 20 кадров/с, час |
|---|---|---|---|---|---|
| 32 | 32 768 | 64 КиБ | 225 МиБ | 5,3 ГиБ | 4,4 ГиБ |
| **48** | **110 592** | **216 КиБ** | **759 МиБ** | **17,8 ГиБ** | **14,8 ГиБ** |
| 64 | 262 144 | 512 КиБ | 1,76 ГиБ | 41 ГиБ | 35 ГиБ |
| 96 | 884 736 | 1,69 МиБ | 5,93 ГиБ | 139 ГиБ | 119 ГиБ |

Цифры на диске указаны до сжатия. Блоки сильно повторяются (воздух, камень, земля), поэтому gzip уменьшит файлы заметно, но во сколько раз, зависит от местности. Проверь на своих записях.

### Оперативная память

| Где | Сколько | Примечание |
|---|---|---|
| Буфер одного кадра в боте | равен размеру кадра (216 КиБ при 48) | создаётся на каждый снимок и передаётся воркеру без копирования |
| Очередь воркера | кадр × число кадров в очереди | растёт, только если gzip не успевает за скоростью записи |
| Палитра | единицы КиБ | зависит от числа разных блоков |
| Чанки, которые держит mineflayer | порядка сотен МиБ | оценка: зависит от версии и view-distance сервера |
| Загрузка записи в Python | кадров × size³ × 2 Б | час при 1 кадр/с и size 48 = 759 МиБ, а вместе с `raw` примерно вдвое больше |

Для обучения удобнее читать запись кусками (по кадрам из потока gzip), а не целиком.
